# 저장 위치와 frontmatter 필드

## 저장 위치와 우선순위

같은 이름의 서브에이전트가 여러 위치에 있으면, 우선순위가 높은 쪽이 사용된다.

| 위치 | 범위 | 우선순위 | 생성 방법 |
|---|---|---|---|
| 관리형 설정(조직 배포) | 조직 전체 | 1 (최고) | 관리자가 managed settings로 배포 |
| `--agents` CLI 플래그 | 현재 세션만 | 2 | 세션 실행 시 JSON으로 전달, 디스크에 저장 안 됨 |
| `.claude/agents/` | 현재 프로젝트 | 3 | 직접 작성 또는 Claude에게 요청 |
| `~/.claude/agents/` | 사용자의 모든 프로젝트 | 4 | 직접 작성 또는 Claude에게 요청 |
| 플러그인의 `agents/` 디렉토리 | 플러그인이 활성화된 곳 | 5 (최저) | 플러그인 설치로 자동 로드 |

- **프로젝트 서브에이전트**(`.claude/agents/`)는 특정 코드베이스에 특화된 경우에 적합하다. 버전 관리에 포함시켜 팀과 공유할 수 있다.
- **사용자 서브에이전트**(`~/.claude/agents/`)는 여러 프로젝트에서 개인적으로 재사용하는 경우에 적합하다. 단, `CLAUDE_CONFIG_DIR` 환경변수가 설정된 환경(여러 계정을 분리해서 쓰는 경우 등)에서는 실제 설정 디렉토리가 `~/.claude`가 아니라 `$CLAUDE_CONFIG_DIR`이므로, 전역 서브에이전트를 만들기 전 반드시 `echo "$CLAUDE_CONFIG_DIR"`로 확인하고 값이 있으면 그 경로 아래 `agents/`에 작성한다.
- 두 디렉토리 모두 하위 폴더로 정리 가능하다(예: `agents/review/`). 식별은 파일 경로가 아니라 `name` 필드로만 이뤄지므로, 같은 트리 안에서 `name`이 겹치지 않게 한다.
- 새 `agents` 디렉토리를 이번 세션에서 처음 만든 경우, Claude Code가 감지하려면 재시작이 필요하다. 기존 디렉토리에 파일만 추가/수정한 경우는 몇 초 내로 자동 인식된다.

## frontmatter 필드 전체 목록

`name`과 `description`만 필수다. 나머지는 필요할 때만 추가한다 — 불필요한 필드는 읽는 사람(그리고 미래의 자신)에게 혼란만 준다.

| 필드 | 필수 | 설명 |
|---|---|---|
| `name` | 예 | 소문자와 하이픈으로 된 고유 식별자. `:` 포함 불가(플러그인 스코프 식별자용으로 예약됨) |
| `description` | 예 | Claude가 언제 이 서브에이전트에 위임할지 판단하는 기준. 구체적으로 작성 |
| `tools` | 아니오 | 허용할 도구 목록. 생략하면 상속 가능한 도구 전체를 물려받음 |
| `disallowedTools` | 아니오 | 상속 목록에서 제외할 도구. `tools`와 함께 쓰면 `disallowedTools`가 먼저 적용됨 |
| `model` | 아니오 | `sonnet`, `opus`, `haiku`, `fable`, 전체 모델 ID, 또는 `inherit`(메인 대화와 동일 모델 사용) |
| `permissionMode` | 아니오 | `default`(승인 요청), `acceptEdits`, `auto`, `dontAsk`, `bypassPermissions`, `plan` 중 선택 |
| `maxTurns` | 아니오 | 서브에이전트가 멈추기까지의 최대 턴 수 |
| `skills` | 아니오 | 시작 시 컨텍스트에 미리 로드할 스킬 목록. 이름뿐 아니라 전체 내용이 주입됨 |
| `mcpServers` | 아니오 | 이 서브에이전트에만 연결할 MCP 서버. 메인 대화에 노출하고 싶지 않은 서버를 격리할 때 유용 |
| `hooks` | 아니오 | 이 서브에이전트에 한정된 생명주기 훅(`PreToolUse`, `PostToolUse` 등) |
| `memory` | 아니오 | `user`/`project`/`local` 중 선택. 세션을 넘어 지속되는 메모리 디렉토리 부여 |
| `background` | 아니오 | `true`면 항상 백그라운드로 실행 |
| `color` | 아니오 | 작업 목록·트랜스크립트에서 표시할 색상 |

## 필드 선택 기준

- **도구를 왜 제한하는가**: 서브에이전트는 좁은 역할을 맡기려고 만드는 경우가 대부분이다. 도구를 제한하면 그 역할을 벗어난 행동을 구조적으로 막을 수 있고, description만으로 행동을 통제하는 것보다 훨씬 안정적이다.
- **모델을 언제 명시하는가**: 반복적으로 많이 호출되는 가벼운 작업(로그 확인, 단순 조회)은 저렴한 모델로 지정해 비용을 줄인다. 복잡한 판단이 필요한 작업은 상위 모델을 명시하거나 `inherit`로 메인 대화와 맞춘다.
- **hooks를 언제 쓰는가**: `tools`/`disallowedTools`로 표현할 수 없는 조건부 제약(예: "Bash는 허용하되 쓰기 SQL만 차단")이 필요할 때 `PreToolUse` 훅으로 검증 스크립트를 붙인다.
