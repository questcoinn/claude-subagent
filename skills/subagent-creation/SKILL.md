# Claude Code Subagent Creation

Claude Code 서브에이전트는 특정 역할에 맞춰 별도 컨텍스트 창, 제한된 도구, 독립된 시스템 프롬프트로 실행되는 전담 워커다. 이 스킬은 서브에이전트를 설계하고 `.claude/agents/` 또는 `~/.claude/agents/`에 실제 `.md` 파일로 작성하는 과정을 안내한다.

## 1. 파악할 것

대화 맥락에 이미 답이 있으면 다시 묻지 않는다. 없으면 다음을 확인한다:

- **목적**: 이 서브에이전트가 전담할 좁고 명확한 작업 범위 (예: "테스트 실행 후 실패 항목만 요약", "SQL 조회만 수행")
- **범위**: 이 프로젝트에서만 쓸지(`.claude/agents/`), 모든 프로젝트에서 쓸지(`~/.claude/agents/`) — `references/scope-and-frontmatter.md`의 표 참고
- **도구 제한**: 읽기 전용이어야 하는지, 파일 수정/삭제가 필요한지, 특정 MCP 서버가 필요한지
- **모델**: 비용을 줄이려면 빠른 모델, 복잡한 판단이 필요하면 상위 모델

서브에이전트는 한 번 만들면 여러 세션에 걸쳐 반복 실행되므로, 범위가 넓고 모호한 에이전트보다 **하나의 일을 확실히 하는 에이전트**가 훨씬 안정적으로 동작한다. 사용자의 요청이 여러 역할을 한 에이전트에 욱여넣으려 하면, 분리하는 게 나은지 먼저 확인한다.

## 2. 파일 구조

```markdown
---
name: <소문자와 하이픈으로 된 고유 식별자>
description: <Claude가 언제 이 서브에이전트에 위임할지 판단하는 기준>
tools: <허용할 도구 목록, 생략 시 전체 상속>
model: <sonnet | opus | haiku | fable | inherit, 생략 시 기본 순서 적용>
---

<시스템 프롬프트 본문: 이 에이전트가 무엇을 어떻게 하는지>
```

`name`과 `description`만 필수다. 그 외 필드(`tools`, `disallowedTools`, `model`, `permissionMode`, `skills`, `mcpServers`, `hooks`, `memory`, `color` 등)의 전체 목록과 의미는 `references/scope-and-frontmatter.md`에 있다.

## 3. description 작성 — 위임 판단의 핵심

Claude는 사용자 요청과 각 서브에이전트의 `description`을 비교해서 위임 여부를 결정한다. 애매한 description은 필요할 때 호출되지 않거나, 관계없는 작업에도 잘못 호출되는 결과로 이어진다.

- 이 에이전트가 **무엇을 하는지**와 **언제 써야 하는지**를 둘 다 적는다.
- 자동으로 적극 위임되길 원하면 "proactively", "즉시 사용" 같은 표현을 넣는다.
- 다른 에이전트와 겹치지 않게, 이 에이전트만의 트리거 조건을 구체적으로 적는다.
- 여러 서브에이전트를 함께 두는 프로젝트라면 description을 짧게 유지한다 — 모든 서브에이전트의 description 합이 커지면 세션 시작 시 컨텍스트를 많이 차지한다.

**나쁜 예:** `description: 코드를 검토합니다`
**나은 예:** `description: 코드 품질·보안·유지보수성을 전문적으로 검토한다. 코드 작성 또는 수정 직후 바로 사용한다.`

## 4. 시스템 프롬프트(본문) 작성

서브에이전트는 Claude Code의 시스템 프롬프트를 물려받지 않고, 이 본문 + 기본 환경 정보만 받는다. 즉 이 본문이 사실상 그 에이전트의 전부다.

- 역할을 한두 문장으로 먼저 명시한다.
- "호출되면 무엇부터 하는지" 순서를 적어준다 — 서브에이전트는 매번 빈 컨텍스트에서 시작하므로 진입 동선이 없으면 탐색에 시간을 쓴다.
- 결과를 어떤 형식으로 보고해야 하는지 명시한다. 메인 대화로 돌아오는 건 이 보고 내용뿐이다.
- 하지 말아야 할 것(예: 쓰기 권한이 없는 에이전트에게 "수정하지 말고 보고만 하라")을 명시한다.

시스템 프롬프트 작성의 일반 원칙(이유를 함께 적기, 금지 행동에 대안 제시하기 등)은 프롬프트 작성 스킬이 있다면 그쪽 원칙을 그대로 따른다.

## 5. 도구 제한 — 최소 권한 원칙

`tools`를 생략하면 상속 가능한 모든 도구를 물려받는다. 이 서브에이전트가 실제로 필요한 도구만 명시하는 편이 안전하고, 역할도 명확해진다.

- 읽기 전용 조사 에이전트: `Read, Grep, Glob` (+ 필요시 `Bash`)
- 코드 수정까지 하는 에이전트: 위에 `Edit`, `Write` 추가
- 특정 위험 행동만 막고 싶다면 `tools` 전체를 새로 적는 대신 `disallowedTools`로 상속 목록에서 빼는 방법도 있다.
- 도구 사용을 더 세밀하게(예: "SELECT만 허용, INSERT/UPDATE 금지") 제어하려면 `hooks`의 `PreToolUse`로 검증 스크립트를 붙인다 — 패턴은 `references/example-subagents.md`에 있다.

## 6. 저장 위치 결정과 파일 생성

`references/scope-and-frontmatter.md`의 표로 범위를 확인한다.

- **프로젝트 전용** → `.claude/agents/<name>.md`
- **모든 프로젝트에서 재사용(전역)** → 파일을 쓰기 전에 반드시 `CLAUDE_CONFIG_DIR` 환경변수부터 확인한다.

  ```bash
  echo "$CLAUDE_CONFIG_DIR"
  ```

  - 값이 설정돼 있으면 `~/.claude/`가 아니라 **`$CLAUDE_CONFIG_DIR/agents/<name>.md`**에 작성한다. 이 환경변수는 Claude Code의 설정 디렉토리 자체를 다른 경로로 바꾸는 용도로 쓰이며, 여러 계정·여러 클라이언트를 분리해서 쓰는 환경에서 흔히 설정돼 있다. 이 값을 무시하고 `~/.claude/agents/`에 쓰면 실제로 로드되지 않는 엉뚱한 위치에 파일을 만드는 셈이 된다.
  - 값이 비어 있으면 기존대로 `~/.claude/agents/<name>.md`에 작성한다(기본값과 동일).

파일명이 `name` 필드와 같을 필요는 없지만, 혼동을 줄이려면 맞춰두는 편이 좋다. 디렉토리가 없으면 새로 만든다. **이미 같은 이름의 서브에이전트가 있다면 덮어쓰기 전에 사용자에게 확인한다** — 기존 서브에이전트는 다른 워크플로에서 이미 쓰이고 있을 수 있다.

## 7. 생성 후 확인

- 사용자에게 작성한 파일 경로와 frontmatter를 요약해 보여준다.
- 해당 세션에서 방금 만든 `agents` 디렉토리가 새로 생긴 경우, Claude Code를 재시작해야 인식된다는 점을 안내한다(기존 디렉토리에 파일만 추가한 경우는 재시작 없이 몇 초 내로 인식됨).
- 필요하면 `Use the <name> subagent to ...` 형태로 바로 테스트해보도록 제안한다.

## 참고 자료

- `references/scope-and-frontmatter.md` — 저장 위치별 우선순위 표, 전체 frontmatter 필드 목록과 설명
- `references/example-subagents.md` — 역할별(읽기 전용 리뷰어, 수정 권한 있는 디버거, 도메인 특화, hooks로 검증하는 에이전트) 예시 패턴

이 스킬은 Claude Code 공식 문서(https://docs.claude.com/en/docs/claude-code/sub-agents)의 서브에이전트 설정 사양에 근거한다. frontmatter 필드나 동작이 문서와 다르게 보이면, 버전에 따라 바뀌었을 수 있으므로 위 문서를 다시 확인한다.

`CLAUDE_CONFIG_DIR`는 공식 문서에 명시적으로 등재되어 있지는 않지만, Claude Code 바이너리에 실제로 존재하며 설정 디렉토리를 `~/.claude`에서 다른 경로로 완전히 대체하는 환경변수로 커뮤니티에서 널리 확인된 동작이다. 미설정 시 기본값은 `~/.claude`다.
